## When to Use

Use when the sequential optimizer (the `cortex-agent-optimization` skill) has hit a local optimum (2-3 consecutive rejections) or when you want to explore the instruction space more broadly before committing to a direction.

## Prerequisites

- An existing optimization project (metadata.yaml, eval table with splits, build script)
- `scripts/build_agent_spec.py` in the workspace (generated by `cortex-agent-optimization` setup — NOT bundled with this skill)
- At least one baseline eval recorded in optimization_log.md
- Python 3.11+ with PyYAML

## Configuration

GEPA uses defaults unless overridden by the user:

| Parameter | Default | Range | Notes |
|-----------|---------|-------|-------|
| population_size | 6 | 4-12 | Candidates per generation |
| max_generations | 10 | 3-20 | Hard stop ceiling |
| mini_batch_pct | 0.30 | 0.20-0.50 | Fraction of DEV questions per gen |
| convergence_threshold | 3 | 2-5 | Generations without improvement before stop |

Mini-batch evals use **1 run per candidate** (noise is inherent to small batches — accept it). Full `runs_per_split` from metadata.yaml applies only in Phase 4 validation.

## Phase 1: Initialize Population

### Step 1: Read Context

Read `metadata.yaml` for all parameters. Read `optimization_log.md` — understand current scores and consecutive-rejection count. Read `DEPLOYMENT_INSTRUCTIONS.md` if present.

### Step 2: Resume or Initialize

Check if `gepa_state.yaml` exists in `<WORKSPACE_ROOT>/<AGENT_DIR>/`:
- **If exists:** Load state. Follow the Resume Protocol (end of this doc).
- **If not exists:** Initialize:
  ```bash
  python scripts/population_state.py init <WORKSPACE_ROOT>/<AGENT_DIR> \
    --pop-size 6 --agent-name <AGENT_NAME> \
    --baseline-fitness <last_accepted_combined_mean>
  ```

### Step 3: Create Population

Load `references/mutation-operators.md` for the operator catalog, weights, and LLM prompt templates.

Create `gepa_population/` directory under `<WORKSPACE_ROOT>/<AGENT_DIR>/`.

For each candidate (1 to pop_size):

1. **Prepare candidate directory:**
   ```bash
   python scripts/mutate.py prepare \
     <WORKSPACE_ROOT>/<AGENT_DIR>/agent/ cand_<N> <WORKSPACE_ROOT>/<AGENT_DIR>
   ```

2. **Register candidate in state:**
   ```bash
   python scripts/population_state.py add-candidate \
     <WORKSPACE_ROOT>/<AGENT_DIR>/gepa_state.yaml \
     --id cand_<N> --generation 1 --mutations ""
   ```

3. **Select mutation operator:**
   ```bash
   python scripts/mutate.py select-operator --weights-file gepa_state.yaml
   ```
   Returns operator name + target file.

4. **Generate mutation (LLM-assisted):**
   ```bash
   python scripts/mutate.py get-prompt <operator> \
     gepa_population/cand_<N>/agent/
   ```
   This outputs a prompt. Use it to generate the mutation via Cortex Code (the agent itself applies the edit based on the prompt, failure context from optimization_log.md, and the operator's intent). Write the mutated content to the candidate's agent/ files.

   For the `add_retry_logic` operator (the only template-based operator): direct application without LLM is acceptable:
   ```bash
   python scripts/mutate.py apply-template add_retry_logic \
     gepa_population/cand_<N>/agent/
   ```

5. **Validate mutation (anti-pattern check):**
   ```bash
   python scripts/mutate.py validate \
     <WORKSPACE_ROOT>/<AGENT_DIR>/agent/ gepa_population/cand_<N>/agent/
   ```
   Rejects: verbose checklists, tool description changes, tool order changes, duplicate of prior rejected mutation.

### Step 4: STOP Gate (supervised mode)

Present population matrix:

| Candidate | Operator | Target File | Mutation Summary |
|-----------|----------|-------------|-----------------|
| cand_1 | add_retry_logic | orchestration_instructions.md | Added 2x retry on transient errors |
| ... | ... | ... | ... |

Show diffs for each candidate. Wait for user approval before proceeding.

## Phase 2: Evaluate Generation

### Step 5: Create Mini-Batch View

Load `references/mini-batch-strategy.md` for stratification rules and rotation constraints.

```bash
python scripts/sample_batch.py <DATABASE> <SCHEMA> <EVAL_TABLE> \
  <DEV_SPLIT_VALUE> --batch-pct 0.30 --generation <G> \
  --history-file <WORKSPACE_ROOT>/<AGENT_DIR>/gepa_state.yaml
```

Execute the returned SQL to create view `<DATABASE>.<SCHEMA>.GEPA_BATCH_GEN_<G>`.

### Step 6: Deploy Candidate Agents

For each candidate:

1. Build spec:
   ```bash
   python scripts/build_agent_spec.py --json \
     --agent-dir gepa_population/cand_<N>/agent/
   ```
2. Deploy:
   ```sql
   CREATE OR REPLACE AGENT <DATABASE>.<SCHEMA>.<AGENT_NAME>_GEPA_CAND_<N>
   FROM SPECIFICATION $$<spec_json>$$;
   ```

If resuming and agent already exists, skip creation.

### Step 7: Fire Evaluations

For each candidate, generate a YAML eval config pointing at `GEPA_BATCH_GEN_<G>` view with unique dataset name `<AGENT_NAME>_gepa_gen<G>_cand<N>_dev_ds`. Upload configs to stage.

Fire all simultaneously (1 run per candidate — no multi-run for mini-batch):
```sql
CALL EXECUTE_AI_EVALUATION('START',
  OBJECT_CONSTRUCT('run_name', 'gepa_gen<G>_cand<N>'),
  '<STAGE_PATH>/config_gepa_cand<N>.yaml');
```

Poll all in parallel using `references/eval-polling.md` pattern until every candidate reports `COMPLETED_METRICS > 0`.

### Step 8: Collect Scores

Query results per candidate:
```sql
SELECT METRIC_NAME, AVG(EVAL_AGG_SCORE) AS MEAN_SCORE
FROM TABLE(SNOWFLAKE.LOCAL.GET_AI_EVALUATION_DATA(
  '<DATABASE>', '<SCHEMA>', '<AGENT_NAME>_GEPA_CAND_<N>',
  'CORTEX AGENT', 'gepa_gen<G>_cand<N>'))
WHERE METRIC_NAME IS NOT NULL
GROUP BY METRIC_NAME;
```

## Phase 3: Select and Evolve

### Step 9: Run Tournament

Load `references/tournament-rules.md` for selection mechanics, elitism, and diversity rules.

```bash
python scripts/tournament.py <scores_json> \
  <WORKSPACE_ROOT>/<AGENT_DIR>/gepa_state.yaml
```

Returns: winners (top half), losers (bottom half), updated operator weights.

### Step 10: Update State

- Record generation results in `gepa_state.yaml` via `population_state.py`
- Update operator weights: winners' operators get +0.02, losers' get -0.01 (floor: 0.02)
- Increment `convergence_counter` if `best_fitness` unchanged, else reset to 0
- Remove eliminated candidates from state:
  ```bash
  python scripts/population_state.py remove-candidates <state_path> --ids <loser1>,<loser2>
  ```

### Step 11: Check Convergence

Load `references/convergence-criteria.md`. Evaluate stop conditions:

| Condition | Result |
|-----------|--------|
| convergence_counter >= threshold | CONVERGED |
| current_generation >= max_generations | CONVERGED |
| All candidates within 2% of each other | CONVERGED (population collapse) |
| No candidate beats baseline after 3 gens | FAILED |
| Gen 1 winner >10% above baseline | CONVERGED (early termination) |

**If NOT converged:**
- Drop loser agents: `DROP AGENT IF EXISTS <AGENT_NAME>_GEPA_CAND_<N>;`
- Drop generation view: `DROP VIEW IF EXISTS GEPA_BATCH_GEN_<G>;`
- Mutate winners to fill empty candidate slots (repeat Phase 1 Step 3 for new candidates only)
- Return to Phase 2

**If CONVERGED (success):** Advance winner to Phase 4.

**If FAILED:** Log failure to `optimization_log.md`, run Cleanup (end of doc), STOP.

---

## Phase 4: Validate Winner

### Step 12: Deploy Winner as Primary

Copy winner's `agent/*.md` files to `<WORKSPACE_ROOT>/<AGENT_DIR>/agent/` (replacing current).
Build and deploy via standard pipeline:
```bash
python scripts/build_agent_spec.py --agent-dir <WORKSPACE_ROOT>/<AGENT_DIR>/agent/
<CLI_TOOL> sql --connection <CONNECTION> --filename deploy.sql
```

### Step 13: Full Evaluation

Run FULL dev eval (all `<RUNS_PER_SPLIT>` runs) — same as `cortex-agent-optimization` optimize/SKILL.md Step 2.
Run FULL test eval — same as `cortex-agent-optimization` optimize/SKILL.md Step 8.

### Step 14: Accept/Reject

Hand off to `cortex-agent-optimization` review/SKILL.md for the standard paired t-test accept/reject decision.

### Step 15: Log and Cleanup

**If ACCEPTED:**
- Log to `optimization_log.md`: `## [GEPA gen <G>]` entry including:
  - Winner's mutation chain (operators applied across generations)
  - Per-generation best scores
  - Total eval calls consumed
- Snapshot winner to `snapshots/<iter_name>/`
- Counts as **1 accepted iteration** for `flag_sweep_baseline.json` revalidation interval

**If REJECTED:**
- Revert `agent/*.md` from last accepted snapshot
- Rebuild and redeploy
- Log rejection with reason

**Always (after accept or reject):**
- `DROP AGENT IF EXISTS <AGENT_NAME>_GEPA_CAND_<N>;` for all candidates
- `DROP VIEW IF EXISTS <DATABASE>.<SCHEMA>.GEPA_BATCH_GEN_<G>;` for all generations
- Remove `gepa_population/` directory
- Remove `gepa_state.yaml`
- Remove GEPA eval configs from stage

## Resume Protocol

On Phase 1 Step 2, if `gepa_state.yaml` exists:

1. Read `current_generation` from state
2. Check if eval results exist for that generation:
   ```sql
   SELECT COUNT(*) FROM TABLE(SNOWFLAKE.LOCAL.GET_AI_EVALUATION_DATA(
     '<DATABASE>', '<SCHEMA>', '<AGENT_NAME>_GEPA_CAND_1',
     'CORTEX AGENT', 'gepa_gen<G>_cand1'))
   WHERE METRIC_NAME IS NOT NULL;
   ```
3. **Results found for all candidates** → Skip to Phase 3 Step 9 (tournament)
4. **No results but agents exist** (check `SHOW AGENTS LIKE '<AGENT_NAME>_GEPA_CAND_%'`) → Skip to Phase 2 Step 7 (re-fire evals)
5. **No agents but `gepa_population/` exists** → Skip to Phase 2 Step 6 (deploy from local)
6. **Nothing exists** → State is stale; delete `gepa_state.yaml` and start fresh

## Cleanup Intent

If user says "gepa cleanup" or "clean gepa agents":

1. Load `gepa_state.yaml` (if exists) → get candidate agent names and generation count
2. If no state file, probe: `SHOW AGENTS LIKE '<AGENT_NAME>_GEPA_CAND_%' IN SCHEMA <DATABASE>.<SCHEMA>;`
3. For each found agent: `DROP AGENT IF EXISTS <DATABASE>.<SCHEMA>.<agent_name>;`
4. For each generation view: `DROP VIEW IF EXISTS <DATABASE>.<SCHEMA>.GEPA_BATCH_GEN_<G>;`
5. Remove local artifacts: `gepa_population/`, `gepa_state.yaml`
6. Report what was cleaned
