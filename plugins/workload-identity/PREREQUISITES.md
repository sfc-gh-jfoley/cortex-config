# Workload Identity Federation Prerequisites

Before invoking wif-setup or wif-troubleshoot, ensure your Snowflake account and external services meet these requirements.

---

## Snowflake Account Prerequisites

### Minimum Edition
- **Required**: Business Critical or higher
- **How to check**: `SELECT CURRENT_ACCOUNT_EDITION();`
- **If not met**: Contact Snowflake sales to upgrade. Standard and Business editions do not support WIF.

### Region Support
WIF is available in the following regions (as of July 2026 GA):

#### AWS Regions
- `us-east-1` (N. Virginia)
- `us-west-2` (N. Oregon)
- `eu-west-1` (Ireland)
- `ap-southeast-1` (Singapore)
- `ap-southeast-2` (Sydney)

#### Azure Regions
- `eastus` (East US)
- `westeurope` (West Europe)
- `southeastasia` (Southeast Asia)
- `canadaeast` (Canada East)

#### GCP Regions
- `us-central1` (Iowa)
- `europe-west1` (Belgium)
- `asia-southeast1` (Singapore)

**How to check your region**:
```sql
SELECT CURRENT_REGION();
```

**If your region is not listed**: 
- WIF support may be coming to your region in a future release. Contact Snowflake support for timeline.
- Alternatively, use API keys or OAuth with key-and-secret-management skill.

### WIF Feature Enabled
- **Required**: Account must have WIF feature flag enabled
- **How to check**: 
  ```sql
  SHOW PARAMETERS LIKE 'ENABLE_WORKLOAD_IDENTITY_FEDERATION' IN ACCOUNT;
  ```
- **If not enabled**: Contact Snowflake support to request WIF enablement. Provide your account ID and organization ID. Enablement typically takes a few minutes.

### CLI Version
- **Required**: `snow` CLI >= 1.2.0 (for `snow connection generate-workload-identity-token` command)
- **How to check**: 
  ```bash
  snow version
  ```
- **If outdated**: Upgrade via `brew upgrade snowflake-cli` (macOS) or `choco upgrade snowflake-cli` (Windows) or download from https://github.com/Snowflake-Labs/snowflake-cli

### User Permissions
- **Required**: Sufficient grants to create secrets and manage external objects
  - `CREATE SECRET` on target schema
  - `USAGE` on schema
  - `USAGE` on database
- **How to verify**: 
  ```sql
  -- Check current role's grants
  SHOW GRANTS ON SCHEMA <schema>;
  SHOW GRANTS ON DATABASE <database>;
  ```
- **If not granted**: Contact your Snowflake account administrator to grant `CREATE SECRET` privilege.

## External Service Prerequisites

### AWS (IAM Role or Lambda)

**Required**:
1. **IAM role ARN** — The role that will assume the Snowflake identity (e.g., `arn:aws:iam::123456789012:role/lambda-exec`)
2. **AWS account ID** — 12-digit account ID (e.g., `123456789012`)
3. **Permissions on IAM role** — Role must allow `sts:AssumeRoleWithWebIdentity` for Snowflake's OIDC provider

**Setup checklist**:
- [ ] IAM role exists in your AWS account
- [ ] Role has trust relationship configured (can be empty initially; wif-setup will add Snowflake OIDC issuer)
- [ ] Lambda/EC2/ECS/other workload is running under this role
- [ ] If using Lambda: function has permission to call Snowflake (via role, no API keys needed)

**Example trust policy after WIF configuration** (auto-generated by wif-setup):
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/oidc.snowflakecomputing.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "oidc.snowflakecomputing.com:aud": "snowflake:account-id:YOUR_ACCOUNT_ID"
        }
      }
    }
  ]
}
```

---

### GCP (Service Account or GKE Workload Identity)

**Required**:
1. **Service account email** — e.g., `my-service-account@my-project.iam.gserviceaccount.com`
2. **GCP project ID** — e.g., `my-project`
3. **Permissions on service account** — Service account must be allowed to use Workload Identity federation via Workload Identity Provider

**Setup checklist**:
- [ ] Service account exists in your GCP project
- [ ] Workload Identity Provider is configured for your GKE cluster (if using GKE)
- [ ] Service account has permissions to call Cloud Functions, Cloud Run, or other workloads
- [ ] If using GKE: Pod service account is annotated with Workload Identity annotation

**Example Workload Identity Pool setup** (auto-managed by wif-setup):
```
Workload Identity Pool: snowflake-wif
  └─ Provider: snowflake-oidc (issuer: https://oidc.snowflakecomputing.com)
      └─ Service account: my-service-account@my-project.iam.gserviceaccount.com (linked)
```

---

### Azure (Managed Identity or AKS Workload Identity)

**Required**:
1. **Tenant ID** — Azure AD tenant ID (e.g., `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`)
2. **Application (Client) ID** — Client ID of the app registration (e.g., `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`)
3. **Subscription ID** — Azure subscription ID
4. **Permissions** — Managed identity must have contributor or custom role on target resources

**Setup checklist**:
- [ ] Managed identity or app registration exists in Azure AD
- [ ] Managed identity is assigned to VM, container, or app service
- [ ] If using AKS: Workload Identity is enabled on cluster
- [ ] Service account in AKS is federated with Azure AD identity

**Example federated credential** (auto-generated by wif-setup):
```
Federated credential type: OIDC
Issuer: https://oidc.snowflakecomputing.com
Subject: snowflake:account-id:YOUR_ACCOUNT_ID
```

---

### Generic OIDC (GitHub Actions, GitLab CI, Custom)

**Required**:
1. **OIDC token endpoint** — URL that issues tokens (e.g., `https://token.actions.githubusercontent.com`)
2. **Issuer URL** — Issuer claim in token (e.g., `https://token.actions.githubusercontent.com`)
3. **Audience** — Value to set in token audience claim (typically Snowflake account identifier)
4. **Subject claims mapping** — How to identify the external workload (e.g., GitHub repo, GitLab project)

**Setup checklist**:
- [ ] OIDC token endpoint is publicly accessible
- [ ] You have test credentials or token sample to validate issuer/audience
- [ ] OIDC provider allows arbitrary audiences (most do)
- [ ] If custom: OIDC endpoint supports `/.well-known/openid-configuration`

**Example: GitHub Actions configuration**:
```yaml
- name: Authenticate to Snowflake
  env:
    SNOWFLAKE_ACCOUNT_ID: xy12345
    SNOWFLAKE_WIF_SECRET: gh-actions-wif
  run: |
    TOKEN=$(curl -H "Authorization: bearer $ACTIONS_ID_TOKEN_REQUEST_TOKEN" \
      "$ACTIONS_ID_TOKEN_REQUEST_URL" | jq -r '.token')
    snowflake-cli connection generate-workload-identity-token $TOKEN
```

## Network and Access Prerequisites

### Snowflake Connectivity
- **Outbound**: App must reach Snowflake's endpoints (port 443, usually automatic)
- **If behind proxy**: Proxy must allow HTTPS to `*.snowflakecomputing.com`
- **Network policy**: If account has network policy, service IP range must be whitelisted

**Verify connectivity**:
```bash
curl -I https://oidc.snowflakecomputing.com
# Should return HTTP 200 OK
```

### Cloud Provider Connectivity
- **Outbound**: App must reach cloud provider's OIDC endpoint (AWS STS, GCP metadata server, Azure login, etc.)
  - AWS STS: `https://sts.amazonaws.com` (or regional endpoint)
  - GCP metadata server: `http://metadata.google.internal` (local, not public)
  - Azure STS: `https://login.microsoftonline.com`
  - GitHub: `https://token.actions.githubusercontent.com`

**Verify connectivity**:
```bash
# AWS (from EC2, Lambda, etc.)
curl http://169.254.169.254/latest/meta-data/iam/security-credentials/

# GCP (from GCE, GKE, Cloud Function)
curl -H "Metadata-Flavor: Google" \
  http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/identity

# Azure (from VM, App Service)
curl -H "Metadata:true" \
  "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2017-09-01&resource=https://snowflakecomputing.com"
```

## Summary Checklist

Before invoking wif-setup or wif-troubleshoot:

### Snowflake Side
- [ ] Account edition is Business Critical or higher
- [ ] Current region is in the supported list (aws/azure/gcp regions above)
- [ ] `ENABLE_WORKLOAD_IDENTITY_FEDERATION` parameter is true
- [ ] `snow` CLI version is 1.2.0 or higher
- [ ] Current role has `CREATE SECRET` privilege on target schema

### External Service Side (choose one)
- [ ] **AWS**: IAM role ARN and account ID available
- [ ] **GCP**: Service account email and project ID available
- [ ] **Azure**: Tenant ID, application ID, subscription ID available
- [ ] **Generic OIDC**: Token endpoint URL and issuer URL available

### Network
- [ ] App can reach Snowflake on port 443
- [ ] App can reach cloud provider's OIDC endpoint (metadata server or STS)
- [ ] If behind proxy: proxy allows HTTPS to both Snowflake and cloud provider

---

## If Prerequisites Are Not Met

| Issue | Resolution |
|-------|-----------|
| Account edition too low | Contact Snowflake sales to upgrade to Business Critical |
| Region not supported | Wait for GA expansion or use API keys temporarily |
| WIF not enabled | Contact Snowflake support with account ID; typically enabled within minutes |
| CLI outdated | Run `brew upgrade snowflake-cli` or equivalent for your OS |
| No CREATE SECRET privilege | Contact account admin to grant `CREATE SECRET` on target schema |
| External service not prepared | Prepare IAM role (AWS), service account (GCP), managed identity (Azure), or OIDC endpoint (generic) |
| Network blocked | Work with security/network team to allowlist endpoints |
